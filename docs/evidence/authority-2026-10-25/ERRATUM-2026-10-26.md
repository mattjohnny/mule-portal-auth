# Erratum to the 2026-10-25 authority verification record

This file corrects [`README.md`](README.md) in this folder. That record is left unchanged
because evidence records are additive-only. Read this erratum together with the record. Where
the two disagree, this file is correct. The corrections come from the 2026-10-25 team review
in issue mattjohnny/mule-portal-auth#11.

## What was merged

PR #10 merged to `main` as `ad0939477ace3684363c63f45840262ee7e261db`. Its tree,
`27b23cdb3a1299a3105ad0fd60d91c3d71c9d499`, is identical to the PR head
`0bc8d41ab59525f02043be26b3c33a8b901762f1`. The merge is untagged and `package.json` still
declares `0.2.4`.

## Corrections

### 1. The `dist/index.js` fingerprint does not match the merged file

- **What the record says:** `dist/index.js` has SHA-256
  `c7b3150aa735e1860b7b539d3f87ecf97b7f7a2b817716ced8514544526963bd`.
- **What is true:** the merged `dist/index.js`, and a fresh build of the merged source, has
  SHA-256 `67da1d837e4ffaa52c6cc5791dcff4c1b99541bf51e1657a4a5c429bcd88d3e9`. The record's
  other two fingerprints are correct: `dist/portal.js` is
  `91bd682cd8a9202d9573fba9abc557adec3ceef8b8c83162e28f89b8b4cb3d62` and `dist/types.d.ts`
  is `04cb0a5f1eb2adbc129bc8a133fd8bcf4e29670ad100515a8df0913f3bbf9f09`.
- **How it was verified:** the committed `dist/` at `ad09394` was hashed. A fresh build from
  that commit was byte-identical to it. No commit in the repository holds a
  `dist/index.js` that hashes to `c7b3150a…`. Rebuilding variants of the source that differed
  only in comments did not reproduce that hash either.
- **What cannot be recovered:** the source that produced `c7b3150a…`. The PR branch was a
  single squashed commit, so the working state the record measured was never committed.
  `c7b3150a…` therefore identifies no artifact that anyone can obtain. The merged artifact is
  identified by the fingerprints under [Merged artifact fingerprints](#merged-artifact-fingerprints).

### 2. The two named Portal counterparts do not exist

- **What the record says:** the original verified Portal counterpart is
  `7480482557688ecbae9270edd6d9a7ed435a227b`, and the publication counterpart is
  `f593c2bc4b4cd57edfb4bf52f4759ff0481f9799`. The repository `README.md` repeats the second.
- **What is true:** neither commit exists in mattjohnny/mule-portal on GitHub. The Portal
  change that shipped is mattjohnny/mule-portal#112. Its head is
  `856fd566b8f2d9e8fd7645849b39169752d5f1f0` and its merge to `main` is
  `638bfeffb251831b2a5efad2be87e64880d27bf7` (2026-10-25). The change is in production:
  on 2026-10-25 the Portal `/health` reported build `eec5443`, and later `608b090`. Both of
  those commits contain `638bfef`. Sources for the two builds:
  - mattjohnny/mule-portal-auth#11;
  - mule-fleet-docs `audits/stability/portal-2026-10-25-608b090.md`, which records
    `/health` returning `build: "608b090"`;
  - its linked freshness record,
    `audits/history/apps/portal/freshness-2026-10-25-eec5443/README.md`, which records the
    Render deploy of `eec5443` and `/health` returning `"build":"eec5443"`.
- **How it was verified:** both named commits were looked up on GitHub and in a current
  Portal clone, and neither was found. `856fd56` and `638bfef` were both found on the
  Portal's `origin/main`. Whether a build contains the merge was checked with
  `git merge-base --is-ancestor`.
- **What cannot be recovered:** the Portal source behind the record's "original
  verification". Results the record attributes to that counterpart, including the 14
  cross-repo cases and the two killed cross-repo mutants, cannot be tied to any published
  Portal commit. The v0.3.0 release re-runs the cross-repo proof against published commits
  instead ([`docs/release/v0.3.0-preflight.md`](../../release/v0.3.0-preflight.md)).

### 3. `dependency-paths.json` is not committed

- **What the record says:** `dependency-paths.json` is the before-repair dependency
  snapshot. Audits, the lock diff, TAP logs and mutation receipts are "retained locally
  beside this summary, outside the commit".
- **What is true:** this folder contains only `README.md` and this erratum. None of those
  files is in the repository, so no reviewer can inspect them.
- **What cannot be recovered:** the before-repair snapshot and the original logs and
  receipts. The lock-only dependency repair the record describes is in the committed
  `package-lock.json`. Its result is re-checked by the clean install below.
